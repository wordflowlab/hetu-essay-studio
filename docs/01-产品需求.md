# 产品需求

## 背景与推导

散文不必服从情节纲要，也不应被迫变成核实表。它的结构可能来自观察与回忆的距离、一个意象反复出现的位置、片段之间的停顿，以及相同材料的不同编排。一次性生成能给出一篇文章，却容易丢失未采用的片段、编排理由和旧意见。软件保存这些结构，Agent理解与创作，作者判断表达。

生成成本和等待时间会变化，但固定作品、历史依据、具体意见与连续审阅仍需长期积累。固定工程避免让模型每轮重建结构；结构化数据与多种阅读方式共用同一专业成果。插件按需安装，让作者提出目标、Agent操作工程、作者在适合的工作面阅读和选择。

## 定义与首版

散文工坊是河图洛书JS／TS专业插件。把观察、意象、片段与不同篇章次序保存为可继续修改的散文工程。用户包括独立作者、编辑与外部Agent。默认旅程：固定作品和已有材料 → 保留观察与回忆的声明 → 准备片段和意象 → 比较不同编排 → 按固定意见局部返工 → 复核旧依据 → 阅读本与下一稿候选。

首版包含完整专业维护、准确来源回读、并行方案、局部备选、意见、改稿影响、上下文、固定交接、JSON／Markdown／HTML工程及专业阅读本。功能必须经机器入口执行，作者可以自然语言提出目标，也保留人工优化入口。

## 边界

文风工坊维护偏好和精修规则；本包维护散文本身的观察、片段与编排。纪实插件维护主张核实，本包不认证记忆和事实，不做旅行预订、日记同步或外部发布。正文、正式设定、素材、采纳与定稿由宿主和作者掌握，不另建数据库、模型渠道或内部Agent。

成功以真实创作、审阅、返工及下一轮接续为准，安装、动作数或文件存在都不足以代表完成。开发与验收状态只由08维护。
