# 工作流程

## 从目标到固定工程

把旧站的雨、母亲的来信和一次虚构等待写成散文。先保留三种材料的性质，用同样片段准备两种次序，比较开头，不替我选定最终版本。先检查活动包、专业Schema和当前WorkRef，读取已存在的工程及原操作。固定作品和已有材料 → 保留观察与回忆的声明 → 准备片段和意象 → 比较不同编排 → 按固定意见局部返工 → 复核旧依据 → 阅读本与下一稿候选。

## 专业方法

原始引文和观察只追加；事实观察、记忆、虚构和借用是提交者声明，不是软件认证。片段固定其观察组合摘要，编排固定片段及独立出场次序的组合摘要。同一片段可以多次出场，但每次出场有独立ID和顺序，不按内容去重。改片段后旧编排、意见和备选明确待复核。新建或改变依据时必须匹配当前摘要，沿原基线未改的旧记录允许保持过期；不能用整本保存绕过快照核验。备选应用固定完整片段摘要，保留其他片段原字节，正文采纳另行决定。

文风工坊维护偏好和精修规则；本包维护散文本身的观察、片段与编排。纪实插件维护主张核实，本包不认证记忆和事实，不做旅行预订、日记同步或外部发布。无材料时明确缺口，不伪造来源。摘录必须从固定原文取得UTF-8区间，get_source分块不等于已读完整原作。

## 返工与交付

先回读具体意见的目标摘要，检查过期；准备备选并比较理由，使用后读取影响报告，按作者意图修订依据。保留未修改内容，不自动重签所有快照。以完整JSON保存专业结构，阅读本供连贯审阅；分块重组后核对完整摘要。

同作品跨包接续固定Owner、对象、revision和sha256，独立剧本与视频各自发现管理能力。下一稿通过实际发现的宿主候选入口准备，专业保存不代表正文采纳。

## 进入作品下一稿

本次目标需要宿主下一稿时，先create_handoff并回读确切专业修订。BasisRef不是宿主任务SourceRef，不能直接混传。通过实际发现的资料任务保存只读派生接续快照：保留专业Owner、对象、revision、sha256、包摘要和实际专业内容，专业事实仍由原插件拥有。再用原材料和快照的固定resource来源准备相应创作任务，回读task_context目录及完整原字节，提交真正的参考稿并回读。没有指定正文目标时不要按名称猜章节；参考稿不等于正文采纳或定稿。
